**When should you work with branches?**

When we are collaborating with other people. When working alone, branches can add unnecessary complexity. But when it comes to collaboration, branching offers a safe way that we can divide tasks and define isolated development paths where everyone can work on a part of the project with minimal conflicts.

**What is the difference between a git clone and a git fork?**

Cloning a repository means copying it from a remote repository to a local directory, allowing us to work on it or use it on a device. In contrast, forking a repository involves creating a new remote repository based on an existing one. The key difference is the destination: cloning is from remote to local, while forking is from remote to remote.

**What is the difference between a fork and a branch?**

The main difference lies in how a repository is managed. When using branches within a repository, every commit needs to be done or approved by the maintainer. In contrast, forking a repository allows for more localized management, enabling contributors to work with greater freedom. This approach allows maintainers to be less involved in the intermediate steps taken to achieve a goal. They only look at the final changes when the forked repository requests a pull.
